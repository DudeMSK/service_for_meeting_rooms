# Бронирование переговорных комнат

Десктопное Windows-приложение, которое читает встречи из нескольких корпоративных Exchange-календарей через EWS и показывает занятость переговорных в режимах «День», «Неделя» и «Месяц».

## Что уже реализовано

- подключение к LanCloud / Exchange EWS по HTTPS с NTLM/NTLMv2 или Basic Authentication;
- чтение делегированных календарей через одну сервисную учетную запись;
- продолжение синхронизации, даже если один из календарей временно недоступен;
- удаление дублей одной встречи, полученной из календарей нескольких участников;
- определение переговорной по полю Exchange «Место» и по ресурсам встречи;
- отдельный раздел «Онлайн встречи» для Teams, Zoom, Яндекс Телемоста и дистанционных событий без физической переговорной;
- удаление из названий локаций суффиксов «Тимс», «Zoom», «Дистант» и других онлайн-каналов;
- постоянный список комнат и псевдонимы через `rooms.json`;
- статусы «Сейчас свободна», «Сейчас занята до…», «Следующая встреча в…»;
- день с временной шкалой, неделя с колонками дней и месячная сетка;
- раздельное оформление календаря и панели переговорных комнат с независимыми темами и акцентными цветами;
- карточка встречи с организатором, временем, местом и исходными календарями;
- фоновое обновление с настраиваемым интервалом и ручная синхронизация;
- безопасная граница Electron: пароль доступен только главному процессу, `nodeIntegration` выключен, `contextIsolation` и sandbox включены;
- пароль из окна настроек шифруется системным хранилищем Windows;
- проверка обновлений через приватный GitHub-репозиторий (кнопка «Проверить обновления» → «Обновить» на вкладке «Общие», см. `INFO_CONTEXT.md`, раздел 9).

## Запуск для разработки

Требуется Node.js 20 или новее.

```powershell
npm install
npm start
```

Для быстрого запуска в Проводнике можно открыть `ERS_MEETING_ROOM.exe` в корне проекта (настоящий EXE-лаунчер разработки, не основной пользовательский запуск).

Локальный файл `.env` уже настроен на переданную учетную запись и исключен из Git. Шаблон без секретов находится в `.env.example`.

## Настройка подключения

Приложение принимает следующие переменные окружения:

| Переменная | Назначение |
|---|---|
| `EWS_EMAIL` | основной SMTP-адрес сервисной учетной записи |
| `EWS_USERNAME` | имя пользователя; допустим UPN или `DOMAIN\\user` |
| `EWS_PASSWORD` | пароль учетной записи |
| `EWS_SERVER` | имя сервера без протокола, например `mail.example.org` |
| `EWS_AUTH` | `ntlm` (по умолчанию) или `basic` |
| `EWS_PATH` | путь EWS, по умолчанию `/EWS/Exchange.asmx` |
| `EWS_MAILBOXES` | SMTP-адреса календарей через запятую |
| `TZ` | часовой пояс, по умолчанию `Europe/Moscow` |
| `REFRESH_MINUTES` | интервал обновления от 1 до 60 минут |
| `GH_TOKEN` | необязательно: токен GitHub для проверки обновлений и публикации релизов в приватном репозитории |

EWS-сервер, тип входа, реквизиты и адреса читаемых календарей являются системными параметрами. Сервер и реквизиты не показываются в пользовательском окне «Настройки», а список календарей выводится как информационное поле без возможности редактирования. Локально сохраненный пароль шифруется через Windows DPAPI. В интерфейсе можно менять часовой пояс, интервал обновления и внешний вид двух областей приложения.

## Внешний вид

В разделе «Настройки календаря → Внешний вид» календарь и панель переговорных комнат настраиваются независимо.

- для календаря: «Как в Windows», «Светлая» или «Темная» тема;
- для панели переговорных комнат: «Как календарь», «Светлая» или «Темная» тема;
- для каждой области отдельно: зеленый, синий, фиолетовый или оранжевый акцент.

При выборе любого из четырех параметров окно сразу показывает предварительный результат. Кнопка «Сохранить» запоминает оба оформления между запусками; «Отмена» возвращает ранее сохраненный вариант. Старые настройки общей темы и акцента автоматически переносятся в новую схему при первом запуске обновленной версии.

## Постоянный список переговорных

В поставляемой конфигурации закреплены четыре физических помещения в заданном порядке: **Москва**, **Магадан**, **Нью-Йорк** и **Кабинет директора по администрированию**. Варианты названий из Exchange (`Офис (Москва) / Тимс`, `ЭРС Групп Магадан (2 этаж)` и другие) объединяются с соответствующей комнатой.

Онлайн-события, в которых нет одной из четырех физических комнат, отображаются в отдельном разделе «Онлайн встречи». Если событие одновременно содержит физическую комнату и ссылку/пометку Teams, оно показывается только у физической комнаты и не дублируется онлайн.

Названия и псевдонимы хранятся в системной конфигурации `rooms.json` и не показываются в пользовательском окне настроек:

```json
[
  {
    "id": "big-room",
    "name": "Большая переговорная",
    "aliases": ["БП", "Переговорная большая", "Room 1"]
  },
  {
    "id": "small-room",
    "name": "Малая переговорная",
    "aliases": ["МП", "Room 2"]
  }
]
```

Если во встрече указано одно из значений `aliases`, событие будет отнесено к каноническому названию комнаты. После изменения файла нажмите кнопку обновления в приложении.


## Важные ограничения Exchange

- У сервисной учетной записи должны быть права уровня Reviewer/«Рецензент» на папку Calendar каждого адреса из `EWS_MAILBOXES`.
- Для определения комнаты организатор должен заполнить поле «Место» либо добавить ресурс помещения к встрече.
- События без физического места учитываются в диагностической статистике, но не занимают переговорную.
- Приложение только читает данные. Создание, изменение и удаление встреч через EWS не выполняется.
